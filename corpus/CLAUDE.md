# corpus: wiki and work tracker for Lantern

This folder tracks work as numbered briefs, the way the owner's other repos do (the corpus-flow
skill), and keeps the wiki: what was decided and why. It was started on 2026-10-27, before any
code.

The repo is public. Everything here is written for a stranger reading it on GitHub: no secrets,
no machine paths, no domain, no usernames, no personal details.

## Layout

```
corpus/
  CLAUDE.md       this file
  index.md        the front door; its catalog is generated by `bash corpus/lint.sh --index`
  lint.sh         health check; exits non-zero on failure
  .planned-roots  top-level folders the briefs have yet to create (the lint's allowlist)
  log.md          chronological record, newest last, absolute dates
  briefs/         numbered work specs: todo/ done/ superseded/
  wiki/           the synthesis pages; status.md says where the work stands, per area
```

## Rules

- A brief is `briefs/todo/<NN>-<slug>.md`: Context, Files you OWN, What to do, Acceptance. NN is
  the highest number across `todo/`, `done/` and `superseded/` plus one, two digits.
- Numbers never change. Finished work moves to `briefs/done/` with the same number and a short
  outcome note added at move time; after that the file is not edited. Work undone later moves to
  `briefs/superseded/` with a one-line note on top.
- Each finished brief gets a `log.md` entry and updates its area's line in `wiki/status.md`;
  briefs run in number order and status.md doesn't list them one by one. Durable findings and
  decisions get a wiki page.
- Every wiki page opens with `summary:` and `updated:` frontmatter, uses standard relative links,
  and stays under 200 body lines. After adding a page or changing a summary, run
  `bash corpus/lint.sh --index`, then `bash corpus/lint.sh`.
- A decision goes in `wiki/decisions.md` only if it is hard to reverse, surprising without
  context, and a real trade-off with named alternatives. Changing one needs an explicit revisit
  and a `log.md` entry. Glossary entries are definitions with an `_Avoid_:` line.
- Absolute dates only.
- Code comments don't cite brief numbers ("brief 03", "(brief 05)"). Say what the code does and
  why; the history belongs in `log.md`.
- Other repos are named, never pathed: "Wicket", "Shelfmark", "Ward" (the `wzd_auth` repo),
  "vps-deploy".
- The app is independent of the owner's other apps (Shelfmark included): patterns may be copied
  from them, but no shared data or cross-app features unless the owner asks.
- Never write the production domain, an API key or a password into the repo. Keys are named by
  their `.env` variable.
- No CI, no pushes, no deploys: the owner pushes and deploys.

## brief-board

Brief progress goes on brief-board. Run `brief-board guide` before you
start or resume a brief, and follow it.
